# Customer delivery brief

## Problem
虚构客户 Acme 的一线支持需要同时查阅 Atlas 产品文档、工厂网络配置和历史事件，排查步骤难以追溯。Nova 用作第二租户，验证客户之间的资料隔离。

## Scope and acceptance
1. E101 / E202 等演示问题能返回授权资料与原始编号。
2. Acme 无法检索 Nova 专属资料，即使问题包含其内部诊断标识。
3. 相同 session ID 在不同租户之间不共享历史和工单。
4. 无匹配资料时请求补充信息，不编造排查步骤。
5. 工单只生成草稿，人工检查后在外部系统提交。
6. 本地启动、Docker 配置、测试与 CI 可复现。

## Pilot plan
先收集 50–100 条由支持工程师标注的真实问题，分离调参与留出测试集。对比当前词法检索与语义混合检索：统计 hit@3、回答忠实度、无依据拒答率、p50/p95 延迟、每次模型请求成本及工单处理时间。没有完成真实试点，因此不报告 ROI 或生产准确率。

## Failure analysis
- 模糊追问可能受最近问题干扰：提供新建会话按钮。
- 资料存在相似关键词但不包含答案：当前阈值只是启发式，需要答案充分性评估。
- 资料过时：MVP 未实现版本生命周期，正式接入需保留生效时间与文档 owner。
- 提示注入：资料标为不可信内容且没有执行工具，但这不构成完整防御。
- 模型服务不可用：返回可理解的 502，切换 demo 模式可独立演示。

## Handover
运行 README 中的命令，验证 `/health`，执行测试和评估，配置独立模型密钥及身份服务后再进入生产评审。
